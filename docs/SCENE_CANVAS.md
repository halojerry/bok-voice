# 场景画布改版方案（Scene Canvas · 一步一画布）

> 2026-09-26 定稿讨论版 v2（Ethan 拍板修正：**场景就是我们的步数**——一步=一场景=一张画布）。
> 对标调研：惜客通 PLUS（xkt.stxc.top）话术编辑器实地摸底。
> 铁律：**画布上画的每一样东西，引擎必须有对应真行为**——UI 不许撒谎。

## 0. 一句话

话术流程 tab 从「一张大画布铺全模板」改成「**步（场景）列 + 每步一张画布**」：
点左列「第 N 步」→ 画布只画这一步的宇宙——步节点（正稿+分支锚点）、
触发它的意图、它能去的终点（跳步目标/收线/转人工/快答/打铃）。
主流程顺序=数组顺序，引擎固有，**不画默认线**；画布上画的每根线=一次偏离。

## 1. 概念映射（惜客通 → 我们）

| 惜客通 | 我们 | 引擎真行为 |
|---|---|---|
| 场景 | **一步（1:1）**：「第一步-画布」 | ✅ 已有：FlowStep |
| 话术节点（卡上全文+分支锚点） | 步（正稿+分支行） | ✅ 已有：prompt 底稿/直念/分支注入 |
| 分支锚点拖线到节点 | `【跳第N步】`标记 | ✅ 已有：`jump_to` 三件套（A-②真栈验收过） |
| 拖到收线 | `【收线】` | ✅ 已有：挂断+结算+热词护栏 |
| 拖到转接坐席 | `【转人工】` | ✅ 已有：notify_human 打铃不暂停 |
| 场景列表 | 步列（第 1..N 步） | ✅ 已有：steps 数组 |
| 跳转节点（跨场景） | 跳步目标 chip（第 M 步不在本画布） | ✅ 同 jump_step |
| 意图/关键词触发 | graph_json intents（作用域含本步） | ✅ 已有：关键词/judge 命中+绑定动作 |
| 按键导航/API节点 | 无 | ❌ 不做（引擎没有） |
| 超时/无内容锚点 | 全局心跳/看门狗 | ❌ 不做（非每分支可配） |

**根本差异（UI 里向运营讲清）**：惜客通的位置和连线=流程本身（引擎无默认推进，
所以每条边都得画）；我们的**顺序=数组顺序，连线=偏离动作**。所以主流程不画线，
每张画布只回答一个问题：「在第 N 步，客户可能说什么 → 我们怎么办」。

## 2. 数据模型与引擎：**零改动**

- **引擎改动 = 无**。一步一场景模型下不存在「多步场景块」，也就没有 v1 草案里的
  场景边界语义（命名场景末步收线）——默认推进（`should_auto_advance`）、末步收线、
  jump/分支动作/意图绑定/QA 快路全部按现状跑。**本方案是纯 web 层重组。**
- `steps_json` / `graph_json` / `published_json` 契约不动。`FlowStep.scene`
  字段保持现状（纯数据位，本方案不消费、不升级）。
- 保存路径全复用既有纪律：步编辑=`updateTemplate({steps_json})` 单键部分更新；
  分支连线=标记写进 ref 行（`composeBranchResp`，round-trip 已钉死）；
  意图绑定连线=`graphDocWithJumpBinding` / `graphDocWithoutIntentBindings`
  （`bindingFromDraft` 字段纪律唯一入口，id/priority/once 不偷改）。
- 画布布局=**固定三列**（触发列 | 步节点 | 目标列），确定性布局，**不存坐标、
  不跑 dagre**。

## 3. 每步画布上有什么（StepUniverse）

```
┌──────────┬────────────────────────────────────────┐
│ 第1步     │  ① 身份确认            [直念]          │
│ 第2步     │  你好，請問係{姓名}嗎…                  │
│ 第3步 ⬅   │  ┌─ 分支锚点 ────────────────┐          │
│ 第4步     │  │ [打错电话]→✆   [要投诉]→(无标记) │      │
│  ⋮        │  └───────────────────────────┘          │
│ + 加一步   │        ╎默认→ 第4步（引擎固有，虚线）     │
│          │                                        │
│ (表单视图) │  触发列            目标列               │
│  切换     │  ●关键词:打错电话   [跳第2步] [跳第5步]    │
│          │  ●判据:想家人      [跳第7步] …(其余步chip) │
│          │                  ✆ 收线   🔔 转人工      │
│          │                  🗣 快答词条  🔔 打铃     │
└──────────┴────────────────────────────────────────┘
```

### 3.1 步节点（画布中央）

- 头：步号 + goal + 直念徽标 + 情绪徽标。
- 身：正稿两行摘要（变量保留）。
- 底：**分支锚点 pill 列**——每分支一枚：条件短语 + 动作图标
  （↩跳N / ✆收线 / 🔔人工 / 无标记=「答完照常推进」）。
- 点节点 → 右侧编辑抽屉：现有 `StepRefForm` 三件表单**原样复用**
  （+goal、直念、情绪）。
- **默认推进虚线**：步节点右侧一枚「默认→」锚，虚线连到目标 chip
  （下一步 / 末步=收线）。标注「引擎固有，不可编辑」——它可视化的是
  `should_auto_advance`，不是数据。

### 3.2 触发列（左）：作用域含本步的意图

- 节点=意图（label + 关键词数 + 判据徽标）。绑定渲染为出线：
  `jump_step`→目标步 chip；`play_qa`→快答词条徽章节点（词条问题摘要）；
  `notify_human`→打铃终点。
- `steps=[]`（全程意图）**不铺节点**：收成画布顶部一条「全程意图 ×N」横条，
  点开是列表（编辑走既有意图抽屉）。防每张画布重复铺同一批节点。
- `steps=[2,3]`（多步作用域）：两张画布都显示，同一份数据，编辑任一处全局生效。
- 意图的新建/关键词/判据编辑=点意图节点开**既有** intent drawer，不新造表单。

### 3.3 目标列（右）

- **跳步目标 chip 列**：其余各步一枚（步号+goal 摘要，可折叠只显已用+展开全部）。
  分支锚点/意图绑定拖线到 chip = 设跳步。
- **固定终点**（不可删）：✆收线（注脚：分支标记/明确拒绝/末步默认三源合一）、
  🔔转人工、🔔打铃、🗣快答（快答只在意图绑定线用）。

### 3.4 连线交互

| 手势 | 效果 | 落库 |
|---|---|---|
| 拖分支锚点 → 步 chip | 该分支设跳步 | ref 行 `【跳第N步】` |
| 拖锚点 → 收线 / 转人工 | 该分支收线/转人工 | `【收线】`/`【转人工】` |
| 点锚点（不拖） | 打开抽屉该分支三件表单 | 同表单保存 |
| 拖意图节点出线 → 步 chip | 该意图绑定=跳步 | graph_json jump_step |
| 点连线（confirm） | 解除动作 | 剥标记 / `graphDocWithoutIntentBindings` |

### 3.5 步列（左栏）

- 项=第 N 步 + goal 摘要 + 徽标（直念/有分支/有意图作用域）。
- 底部「+ 加一步」；**删步/排序留在表单视图**（两视图并存共用草稿与
  StepRefForm，画布视图=看与连线，表单视图=重排增删）。

## 4. 不做（v1 明确出界）

超时/无内容锚点、每节点 打断/等待/短信/意向打标、按键导航、API 节点、
prompt 总览任何改动、节点位置参与顺序、坐标持久化。
旧「全模板大画布」**删除**；表单视图保留。

## 5. 测试与验收

- **Python：零改动零新增**（引擎没动；既有 `test_flow_controller.py` /
  `probe_branch_action.py` 全量回归即验收基线）。
- **Web node**：`stepUniverse` 派生纯函数（步+图+qa → 节点/锚点/虚线/出线）、
  锚点↔标记 round-trip（复用既有）、意图作用域过滤、全程意图收起逻辑。
- **真浏览器**：步列导航、加步、锚点拖线/解绑、意图出线/解绑、默认虚线只读、
  表单↔画布双视图草稿一致。

## 6. 施工顺序（引擎零改动 ⇒ 直接 web 层起步）

| 期 | 内容 | 出口 |
|---|---|---|
| P1 | web `stepUniverse` 纯函数 + node 测试 | node 测试绿 |
| P2 | StepCanvas（步列+画布+抽屉复用+连线） | tsc/build 绿 |
| P3 | 切入 studio 话术流程 tab、删旧画布、真浏览器验收 | 验收清单全绿 |

引擎先行那条腿不存在了——这版方案没有引擎腿，是它最大的优点。
