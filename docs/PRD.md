# Bok Voice 产品需求文档

## 背景与目标

用 AI 语音助手替代 20–50 人规模的客服/销售外呼团队。本地优先、可迁云；既能真实业务外呼/接听，也能用于客服训练。

## 用户与角色

- 操作员（operator）：建档、发起/监听通话、查看结算。
- 管理员（admin）：账号、对象、知识库、人设、Provider、成本策略、合规。
- 主管（supervisor）：实时旁听、暂停 AI、接管说话、转人工。

## 核心场景

建档（可表格导入）→ 拨号/接听 → AI 对话（带我方身份 + 对象档案 + 历史 + 产品资料）→ 挂断 → 自动结算 → 下次续聊。

## 身份与模式

三种身份：

- 账号 / 使用者：数据拥有者（你/同事/每个客服）。
- 对象 / 联系人：AI 对话的对方（越南采购商、客户经理…带角色、语言、背景、电话）。
- AI 我方人设：账号/组织级配置（叫什么、代表哪家公司、说话风格）。

两种通话模式：

- `simulation`（训练）：AI 扮演对象，对话人是操作员。
- `live`（真实业务）：AI 扮演我方，对话人是对象/客户。

## 成功指标

- 通话首包可感知延迟 P95 < 1200ms。
- 通话接通率 ≥ 99%。
- 挂断结算完成率 ≥ 99%。
- 知识检索命中率 ≥ 90%（验收样本）。
- 主管接管成功率 ≥ 99%。

## 当前实现状态（已验证）

- WebRTC 本地自托管：浏览器进房 + Agent 派发通过（`tools/browser-e2e`）。
- 多账号业务与向量数据：PostgreSQL + pgvector；Bok Markdown 作为事实源 + 持久索引。
- Agent 端：拉取对象/人设/知识 → `ContextInjector` 注入（不含原始历史正文）→ LLM → TTS。
- 挂断自动结算：指标、通话文档/结算文档路径、对象主题（骨架）；全局洞察蒸馏待完成。
- 确定性 CI 端到端：知识落盘/检索隔离/对象人设拉取/注入知识→指定话术输出/结算。见 `scripts/e2e_pipeline.py`。

## 边界（尚未实现 / 后续里程碑）

- 真实 PSTN/SIP 接入（M6）。
- whisper（主管私语）。
- 服务端多租户认证 / SSO（本地 profile token）。
- 完整坐席工作台（主管台 v1 已含旁听/暂停/接管/转人工，接管为 API 级）。
- 全局洞察蒸馏与对象历史主题合并（骨架保留）。
