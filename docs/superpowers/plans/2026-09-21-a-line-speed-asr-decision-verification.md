## 0. 这份计划是什么、不是什么

**是**：一组**不改仓库源码、不改任何默认配置、不重启在跑的任何服务**的测量。把候选方案（LAY A、LLM2Jev 式
typed decision、热词扩容、输出端校正、Qwen 4B 参数档位）从「机制上讲得通」推到「本机跑出来是多少」。

**不是**：实现。本文里所有「可能的修法」都只是**待验证假设**，验证通过才进后续的修复计划。

## 2. 决定计划形状的五个前期发现

### D1 ⭐ mlx-lm 原生支持「只 prefill 不生成」的判类型决策——这条最值钱

两件事凑在一起：

1. mlx_lm server 的请求体支持 **`logprobs`（1-10）** 与 `max_tokens`；
2. 参考项目 **LLM2Jev**（Yinsongxu/LLM2Jev，apache-2.0）的核心方法正是 **"prefill-only binary inference"**
   ——不要求模型「生成一个标签再解析」，而是问一个是非题、**只读下一个 token 的概率**，从不真的自回归解码。
   该项目同样接受运行时定义的 **Choice / Score / Noul** 三类问题，与 LAY A 是同一个接口形状，
   区别是它**不训新模型**，用本地现成的 HF 模型跑（经 `--model-path` 指定）。

**合起来的意义**：我们**可以在现有 mlx_lm server 上用现有 4B/9B，做同款 typed decision，零新依赖、
零新运行时、零仓库改动**（一个 curl 就能验）。可行性论证见 §3 V-1。

**为什么这条比 LAY A 更重要**：它直击 `docs/A_LINE_LOGIC.md` §10.4 那个「迟一轮」的结构洞。
当前 L4/L5 之所以需要 pending 槽 / TTL 一轮 / store 守卫 / 单飞 / fire-and-forget / 下一轮消费，
**唯一原因是 judge 是 9B 生成模型、慢到只能异步**。判定从「生成自由文本再正则解析」改成「读一个概率」，
这套异步脚手架就不再必要——不是优化，是**可以整块删掉**。

### D2 LAY A 在我们机器上**没有 MLX 路径**

- mlx-lm 的 `mlx_lm/models/` 架构目录里**没有 ModernBERT / mmBERT** → 无法用 MLX 跑；
- LAY A 官方只提供 `pip install laya`（PyTorch + transformers），模型卡与 PyPI 页**均未提 MPS / Apple Silicon**；
- 模型卡自己的 CPU 数字：预载后 **193–464 ms/问**，CPU 重载 **7.4 s**，懒路由语言切换 **7–10 s**；
- 那个诱人的 **32.8 ms 是 T4 的数字**——我们没有 T4。

**判定**：LAY A 的 33ms 对我们不成立。CPU 档 193–464ms **高于**「同轮同步」预算（判据表见 §3 V-1），
MPS 能否进 300ms 未知，且 PyTorch 在一个纯 MLX 本地栈里是**第二套运行时**。
→ **LAY A 降为 V-1 的 Track B（对照组），不是主路。**

### D3 LAY A 的**接口**是对的，而我们可以用自己的模型实现它

LAY A 的 `criteria` 是 `{标签: 描述}`、**推理时逐次传**——这个接口设计是对的，也正是「意图词预填充」的
天然容器（运营写一次，模型当选项集用，无需训练）。

既然 D1 已证明我们能用 MLX 做同样形状的 `choice / noul / score`，那么
**「LAY A 的接口」与「LAY A 的模型」是可以分开取的**：取接口（typed decision + 运营给的 criteria），
模型用我们自己的、已经热的、原生 MLX 的 4B。这是 V-1 Track A 的理论基础。

### D4 `--kv-bits` 会杀掉 batching（禁用项，不是候选）

mlx-lm `SERVER.md` 原文：量化 KV cache **不支持 batching**，该模式下服务**串行处理请求**。
我们是 4–6 路并发会话——开 `--kv-bits` 等于杀掉并发。**列为禁用项**。

### D5 ASR 侧：模型对粤语不差，缺的是**输出端校正层**

Qwen3-ASR 官方卡数字：**粤语 Fleurs-yue 3.98 / WenetSpeech-Yue 5.82 \| 8.85** / CV-yue 7.57；
官话 WenetSpeech 4.97 / AISHELL-2 2.71；52 语言方言，明确列出 **Cantonese (Hong Kong accent) /
Cantonese (Guangdong accent)**。模型侧并不弱。

而我们的实弹问题（九→狗、號→后 同音滑失，京|東 品牌词拆分）是**特定词在特定上下文里输了**。
到目前为止我们用过的全部手段都在**输入端**：热词 context 偏置（≤200 字符）、8bit 维持、
跨段 join-hold、句级/子句/长度提交。**输出端从来没有过校正层**——
把已知词表 + 数字语法 + 对象词（courier / tracking_tail / contact_channel）+ 模板变量拿来做**一次受约束的
后校正**，这个杠杆**从未试过**。→ V-3 的新线。

## 3. 五条验证线

### V-1 决策层选型（最高优先：决定 §10.4 结构洞能不能消掉）

**问题**：能否在 <300ms 内、用我们自己的模型，对一轮转写给出「意图归属 / 是非判断 / 强度分」？

#### Track A —— MLX prefill-only typed decision（主路）

| 步 | 动作 | 会暴露的第一个问题 |
|---|---|---|
| A1 | 对 :1235 发 `POST /v1/chat/completions`，`max_tokens: 1`，`logprobs: 1-10`，prompt 构造为「……只回答 是 或 否」 | **响应形状**：mlx_lm server 回的是 `logprobs` 还是需要 `top_logprobs`、回几个候选、中文单字是否独立成 token。若拿不到 top-k，就得改问法（如让模型输出单个数字 token） |
| A2 | 读 `是` / `否` 两个 token 的 logprob → P(是) | 4bit 权重下**概率分布是否还有判别力**（见下「最大风险」） |
| A3 | 用真库副本的 N=30 条真实转写（**含 L-① 漏网轮**），构造三类问题各跑一遍：`choice`（本步归属，选项 = 该步 scope 内图意图标签）、`noul`（是否拒绝 / 是否报号 / 是否应承）、`score`（情绪强度 3 档） | — |
| A4 | 记：单问端到端墙钟（含 prefill）、P 值分布直方图、与现有 L1/L3 输出的**一致/不一致清单** | — |

**最大风险**：我们的 4B 是 **4bit** 量化，而量化会**劣化概率分布**——若 P 值糊成一团没有判别力，
Track A 就需要先解决量化档位（48GB 内存无压力，可试 8bit 4B，代价是显存与速度），或退回生成式。
**这是本计划里最需要尽早知道答案的一件事，A1-A2 半小时内能出结果。**

#### Track B —— LAY A 对照（可选项）

| 步 | 动作 |
|---|---|
| B1 | **独立 scratch venv**（不污染 `.venv312`）：`pip install laya`；记实际拉进来的 torch 版本与体积 |
| B2 | device 探测：MPS 可用否、加载 mmBERT-base 要多久、单问延迟。**若 >1s 直接判死，不必往下跑** |
| B3 | 同一批 30 条转写 + 同一批 criteria（用运营真词表），跑 `laya-multilingual` |
| B4 | 与 Track A 逐条对照 |

**注意**：zh / cantonese 必须走 `laya-multilingual`——模型卡自陈英文 checkpoint 在非拉丁文字上
「stays confident while being wrong」（高棉语 0.000 准确率 @ 0.952 置信），
而 **confidently wrong 恰恰是收线场景最危险的失败模式**。

#### 判据表（同步可用性）

| 单问延迟 | 判定 |
|---|---|
| **< 300 ms** | 可同轮同步 → **L4/L5 的 pending / TTL / store 守卫整套可删** |
| 300 ms – 1 s | 需与别的东西重叠，架构收益减半 |
| > 1 s | 只能继续异步 → 无架构收益，退为「提升召回」用途 |

300ms 这个门槛的依据：当前垫音链发能覆盖的等待窗是 ~1.5–2.3s，判定若落在 300ms 内
则**不需要任何垫音**就能同轮完成，体感上等于「零等待」。

### V-2 LLM 提速（活通话主路径）

**问题**：现有 4B 的 TTFT 还能不能压。

| 步 | 动作 | 约束 |
|---|---|---|
| 2.1 | **`--prefill-step-size` 重 A/B**：现设 512，依据是 2026-09-08 那次二分（512 优于 1024，官方默认 2048）。**但那次是哪台机器上做的？** 若在 16GB 机上，结论不保证迁移到 48GB | **在空闲端口（如 :1239）起第二个 mlx_lm server** 加载同一颗 4B，`--prefill-step-size 2048`，同一批 prompt 对打。**绝不重启 :1235** |
| 2.2 | **`iogpu.wired_limit_mb`**（macOS 15+，`sudo sysctl`）。mlx-lm 文档提到大模型下有收益 | ⚠️ **动的是系统级参数、影响同机所有会话（含别人在跑的栈）→ 需显式批准才做**；必须留改动前读数、事后可回滚 |
| 2.3 | **并发退化**：4–6 路时 TTFT 劣化多少 | 用 `scripts/load_audio_concurrency.py` 的口径但**降到 2 路并缩短**，避免压到真实会话。基线从 `llm.log` 的 `LLM_TTFT_MS ... cached=N/M` 取样 |
| 2.4 | **明确不测**：`--kv-bits`（D4：杀 batching）；`draft_model` 投机解码（AGENTS.md 记录会关 continuous batching —— 列为**待复核**，因为若它其实不关，4B 上投机收益可能不小） | — |
| 2.5 | **量化档位**：现 4bit。若 V-1 需要更干净的 logprob，同端口 A/B 8bit 4B | 内存无压力，代价是显存与速度 |

### V-3 ASR 提准

**问题**：剩下那些同音字滑失 / 品牌词拆分，能不能在**输出端**救回来。

| 步 | 动作 | 备注 |
|---|---|---|
| 3.1 | **热词边际复核**：复用 `scripts/probe_hotword_ab.py`（三档 none/current/extended × 10 碎裂句） | 2026-09-17 那次的结论要在这台机器上重跑一遍（模型/硬件可能都变了）。注意当年已发现**探针有 ±2-3 句渲染方差**，必须跨渲染采样 |
| 3.2 | ⭐ **输出端受约束校正（新杠杆，从未试过）**：离线拿历史转写，用「热词表 + 数字语法 + 对象词（courier / tracking_tail / contact_channel）+ 模板变量」做后校正，看能修回多少 | 零代码做法：真库副本导出转写 → 纯文本规则在 `/tmp` 脚本里跑（经 Write 工具，**不进仓库**）→ 对 E2E 固定句集量 CER 前后。**这是「加一层」不是「改一层」**，不碰 `_echo_filter` / join-hold |
| 3.3 | **数字专线**：号码捕获现在是 4 位起收 + `_digit_normalize`。离线统计真实报号轮里 ASR 究竟错在哪几个数字上 | 这是「零降级铁律」的核心区，值得单独一张表 |
| 3.4 | **云杯对照（可选，需 key）**：Qwen3-ASR 卡提到 DashScope 有实时 / FileTrans API。同一批真实音频离线跑一遍比 CER | **判断点**：提升 <2 个点 → 不值得引入网络依赖；>5 个点 → 值得讨论混合路由。<br>⚠️ 这条是唯一的**外部**请求路径，若要走，服务端侧必须先有 host 校验（拒绝回环/私有/保留地址） |

### V-4 意图词预填充可行性

**问题**：把现有词表当 `criteria` 喂进去，零样本命中率够不够。

| 步 | 动作 |
|---|---|
| 4.1 | 从真库副本构造「每步的意图词集合」：步骤 `goal` + `ref` 首行 + 分支 `cond` + 图意图 `keywords` + **`qa_entries.question_text`（按 `scope`/`step_index` 归属到步）**。**这一步本身就会暴露覆盖率问题**（哪些步一个词都没有） |
| 4.2 | 用 V-1 Track A 的 logprob 决策，对 L-① 漏网轮跑 `choice`，看能否把「关键词没中」的轮次判对 |
| 4.3 | ⭐ 这张表**同时就是 O 类问题的登记表**：哪一步没词、哪条 QA 从没被当成意图语料、哪些词互相冲突 |

**为什么 4.1 值钱**：`source=mined` 的那些 QA 问法是**从真实通话里挖出来的客户原话**，
今天**只**用于 0.90 字面匹配，**从未被当成「该意图的示例说法」提供给意图层**。
它们恰恰是最好的示例说法。这一刀切下去，话术意图与 QA 就共享了同一个词表——
不需要把两个系统合并（那会毁掉 QA 作为独立召回通道的正交性），只要让 QA 的问法**同时**充当意图语料。
这是 `docs/A_LINE_LOGIC.md` §10.9「共享词表、各留判据」的具体第一刀。

## 5. 产出与执行顺序

**本轮结束时的交付**：

1. V-1 … V-5 各线读数与判定（含 Track A/B 对照表）
2. **问题登记册**（预计 15–30 条）
3. **决策层选型建议**（Track A / Track B / 维持现状），带数字
4. 由 1–3 导出的**修复计划**（分优先级，每条带预期收益与风险）

**顺序建议**：

```
V-1（先行：它决定要不要动 L4/L5 架构，也决定 V-4 用什么工具）
 ├─ V-3（并行：ASR 独立、且是准确度的大头）
 ├─ V-2（插空：需起第二实例，别和 V-1 抢机器）
 └─ V-4（依赖 V-1 的 Track A 结论）
V-5 收尾全跑
```

**写在前头的风险**（避免中途才发现）：

- **4bit logprob 不可用**会让 Track A 必须先解决量化档位问题——所以 A1/A2 要最先做；
- **第二实例 + LAY A + 探针同时跑会在 48GB 上抢 GPU**，读数互相污染 → **串行执行，单次只跑一条线**；
- 真库副本导出前先确认对象/号码都是测试数据。
- V-2.2（`iogpu.wired_limit_mb`）是唯一需要**显式批准**的系统级动作。

### 6.1 延迟与准确率（决定性数字，4B vs 9B 同一把尺子）

统一仪器：`/tmp/v1g_prod_cache_ab.py` —— 同一份「按步静态 system（12 候选表）」，7 句真实口吻转写，
ground truth 人工标注，**缓存开 / 破缓存两档对照**。

| 形状 | 4B :1235 | 9B :1237 | 判据 300ms |
|---|---|---|---|
| **生产形状 · 缓存吃满** | **6/7 · 平均 176ms** | **7/7 · 平均 413ms** | 4B ✅ / 9B ✗ |
| 破缓存（前缀不复用） | 6/7 · 180ms | 7/7 · 1006ms | — |
| 短 prompt 暖（~65 tok，`v1b`） | median 158ms | median 408ms | — |

**三条结论**：

1. **前缀缓存的收益是 2.4–4×，且不损失准确率**（同题同分，只是变快）——
   由 A/B/C 三变体隔离确认（见 6.3），不是猜的。
2. **4B 在生产形状下 176ms，稳在 300ms 判据内**；9B 413ms，**超出**。
3. **准确率上 9B 略优（7/7 vs 6/7），但只差一例、样本 n=7，不足以定论。**
   那唯一一例是英文句「Hello, is this about my parcel?」——9B 正确判 `查詢進度`，4B 判成 `問平台資料`。
   **准确率结论必须等 V-4 用真实挖掘语料放大样本后再下。**

**⭐ 但这里有个战略要点，比"选哪个模型"更重要**：**收益来源不是"用 4B"，而是"把生成式判定换成 prefill-only 判类型判定"。**
9B 即使 413ms，对比现状（生成式 judge，`timeout=20s`、迟一轮、需要 pending 槽/TTL/store 守卫）
仍然是**几十倍的提速 + 同轮同步**。所以：
**4B 用来做「必须 <300ms 的同步判定」；9B 用来做「可以多花 400ms 但要求更准的判定」——两者按判定用途分工，不必二选一。**

### 6.2 判定质量

| 测项 | 4B | 9B |
|---|---|---|
| `noul`（14 例，label 修正后） | **14/14** | 标定失败，该栏作废（见 V1-05） |
| `choice`（6 选项，5 例） | **5/5**，margin 干净（正确项 1.000） | 5/5 |
| `choice` 基数扫描（3/6/9/12 选项） | **6/6 · 6/6 · 6/6 · 5/6** | **6/6 · 5/6 · 5/6 · 6/6** |
| `choice` 位置扫描（12 选项，正确位 1..12，字母标记） | **2/12**（锁死答 B） | **12/12**（无位置衰减） |
| 生产形状（7 例 ground truth） | 6/7 | 7/7 |

`noul` 两个原始「miss」经复核是**我的标注错了**，不是模型错：「你係邊個？」答 否、
「我再考慮下」答 否 都更贴语义（原标签问的是"质疑真实性"/"明确拒绝"）。
补测「同一句话、换问题问」两例全部正确 —— **验证了 typed decision 的真正卖点：问题本身就是判据规格**，
同一句话在不同问题下给出不同答案（N9 否 / N9b 是；N10 否 / N10b 是）。

**⚠️ 「12 选项退化」的结论已被两次更正**：第一版归因「基数」，基数扫描推翻；
位置扫描在 4B 上重现了退化（2/12），但生产形状对照又把它推翻（见 6.3）。**最终定性见 6.3。**

### 6.3 三次更正后的最终定性：位置扫描的异常是**窄条件触发**，不污染生产形状

| 实验 | 形状特征 | 4B | 9B |
|---|---|---|---|
| 位置扫描（`v1e`） | **12 次请求 user 轮完全相同，选项表只挪动一项** | **2/12**（10 次答 B） | 12/12 |
| 缓存 A/B（`v1f`） | 同上，加唯一 nonce 破缓存 | **10/12** | — |
| **生产形状 A/B/C（`v1g`）** | 静态 system + **每句不同的 user 轮** | **三个变体全 6/7**，连失败的都是同一例 | 7/7 |

**定性**：`v1e` 那个 2/12 是**真实存在但触发条件很窄**的现象 —— 需要
「user 轮逐字相同 + 选项表只做单点位移」这种**非自然输入**。
一旦回到生产形状（客户那句话每次都不同），**三个变体给出完全相同的答案与相同的唯一失败例**，
说明**前缀缓存不污染判定**。`v1f` 里 nonce 一加就从 2/12 变 10/12，但 `v1g` 证明那不是"缓存坏了"，
而是**破缓存同时改变了模型对近同文上下文的注意力**——两者纠缠，**机制仍未查清，已登记为 V1-11**。

**⭐ 顺带测出并写进实现约束的**：候选表放「按步静态」system 前缀 → **176ms**；
放 user 轮里逐请求变化 →（`v1d`）**348ms**。**候选清单必须进静态前缀。**

### 6.4 仍然成立的阻断性发现

1. **logprob 不是归一化分布**（V1-03）：`Σtop10 = 1.001 … 1.052 > 1`，10/14 样本越界。
   数学上不可能是 softmax。→ **`exp(logprob)` 不能当概率用**：排序可信、**绝对置信度不可信**。
   直接后果：**`noul` 不能作为合规闸的置信度依据**（「P(收线)=0.88」并不意味着 88% 该收线）。
   阈值只能**逐问题在真数据上经验拟合**。
2. **token 字符串乱码、只能按 `id` 比对**（V1-02）：同一响应里 `message.content` 是正确的「是」，
   而 `logprobs.*.token` 是 `æĺ¯`（码点 0xE6/0x13A/0xAF）。
   → 实现必须**按 token id 建映射**。（首轮探针 17/17 假 miss 的根因。）
3. **阿拉伯数字 ≥10 不是单 token**（V1-10）：`max_tokens=1` 下 "10" 读到的是 "1"，
   标定 12 个数字只成功 9 个。→ **标记必须用保证单 token 的符号**（ASCII 字母 A–L 实测 12/12）。
4. **服务端入参不校验、直接断连**（V1-01）：`top_logprobs > 10` 时不返 400。

## 7.5 ⭐ 真实语料对照：一致率 20%，且它把优先级整个改了

探针 `/tmp/v1h_agreement.py`。语料取法：CP `/api/calls?limit=400` 轮询 `/api/calls/{id}/turns`，
筛 `line=="a"` 且 `role=="user"` 的真实客户转写，去重取长度 2–60 的 30 条。**全程只读，不写库。**

| 模型 | 墙钟 | 一致率 |
|---|---|---|
| 4B :1235 | median **242ms** / p90 251 | **6/30 = 20%** |
| 9B :1237 | median **318ms** / p90 330 | （同上） |

**一致率只有 20% —— 两个模型在 30 条真实转写上有 24 条判得不一样。** 但看分歧样本，
结论不是"选型很重要"，而是**被判定的东西本身已经坏了**：

| 真实转写（原文照录） | 问题类型 |
|---|---|
| 「好。我想了解一下**女**。」「你好。我想了解一下**女**。」 | **同音字滑失**（你→女） |
| 「想查下我账单，**去天热道尔道个**。」「查下我张丹**去天热道玩道个**。」 | 整段退化，非语言 |
| 「你帮我睇**。**一下。」「你帮我睇**。**底下。」「快，你帮我睇。」 | **碎裂提交**（句号=微停顿切轮） |
| 「查下我。**我张单，麻生**你帮我推下。」 | 碎裂 + 同音（麻煩→麻生） |
| 「Hello. I would like to know more about **your**.」 | 外文截断 |
| 「旗下。」「地下。」「底下。」 | 纯碎片 |

**两个模型的失败方式不同，且都反映输入已坏**：
- **4B 塌向单一标签 `F`（問平台資料）** —— 对受损文本给出一个**恒定答案**，是危险的失效模式
- **9B 分散到 `L`（其他）/`A`（查詢進度）/`D`/`B`** —— 大量落到「其他」，对垃圾输入反而是更诚实的答案

**这条发现把优先级改了**（原先 V-1 排第一）：

1. **决策层不是瓶颈，ASR 转写质量才是。** 我们在拿一块坏掉的文本去问"它属于哪个意图"——
   无论换 LAY A、换 4B、换 9B，都是在坏输入上做分类。
2. **`V-3`（ASR 提准）应当升到 `V-1` 之前**，尤其是 `V-3.2`（输出端受约束校正）
   与 `V-3.3`（数字/同音专线）——它们直接改善的是**判定层的输入**。
3. **决策层选型不得在受损语料上定**：`§6.1` 的 6/7 vs 7/7 是干净语料上的数；
   真实语料上 20% 一致率说明**两模型都不可信**。选型结论必须等 ASR 改善后重测。
4. **4B 的"塌向单标签"是独立风险**：即使输入干净时它表现好，一旦输入退化它会给出**恒定答案**，
   而恒定答案在客服场景意味着**系统性答错**。这条给 `§6.1` 的"4B 更实用"打了一个折扣，
   也说明**必须有置信度/一致性护栏**——但见 `V1-03`：logprob 未归一化，护栏不能直接用它。

### 9.1 V-3.1 热词边际归零

**`extended` 相对 `current` 逐句零增益**（唯一增益句 7 来自 `current`）。

**⚠️ 方法论修正（第 4 次差点被测量骗，这回先拦住了）**：本探针**每句只合成一次音频、三档两轮共用同一条**，

### 9.2 V-3.2 输出端音学校正：上界只有 4–5/10，且有 8 路歧义

用 pypinyin + ToJyutping（装在**独立 scratch venv** `/tmp/v32venv`，不碰项目 `.venv312`），
对每个关键词在转写里做**等长**音近定位（音节级编辑距离，普通话/粤拼两侧取优、去声调）：

| 定位结果 | 句数 | 说明 |
|---|---|---|
| 距离 0 原样在 | 3 句 | 機器人 / 好講 / 邊度 —— **本来就对，校正零收益** |
| 距离 1 唯一候选 | 5 句 | 單號←单后、幾多←劲多、賠到←皮到、詐騙←再骗、證明←整改 |
| **1 字关键词 8 路歧义** | 2 句 | 嬲、倉 —— 对**任意单字**都是距离 1，无法判别 |
| 不可定位 | 若干 | 呃人 / 賠償 / 多少 / 號碼 —— 正确的音在转写里**不存在** |

→ **输出端校正的真实召回上界 ≈ 4–5/10**（3 句已对 + 2–3 句可信候选），
且必须「只打多字关键词 + 只接受唯一候选」才能压住假阳性（`再骗`/`整改`/`劲多` 都可能是真实短语）。

**⚠️ 第 5 次测量错误（已修正）**：本测试第一版允许滑窗长度 ±1，导致
「2 字关键词 vs 任何单字」= 删除距离 1、「1 字关键词 vs 任何字」= 替换距离 1，
汇总**假出「10/10 可救」**。改成等长后才得到 4–5/10 的真实上界。
**教训：编辑距离类指标必须禁止长度不等，否则会退化成「文本里有没有字」这种恒真判据。**

### 9.3 ⭐ V-3 关键对照：语义不能吸收 ASR 损伤（猜想被证伪）

`/tmp/v3b_semantic_vs_repair.py` —— 同一批 10 句，同一份 12 选项表，两臂对照：

| 模型 | clean（源句） | **asr（损坏转写）** | 衰减 |
|---|---|---|---|
| 4B :1235 | **9/10** · 268ms | **4/10** · 238ms | **−5** |
| 9B :1237 | **10/10** · 371ms | **6/10** · 314ms | **−4** |

**两个结论，一个正面一个致命**：

1. **正面：typed decision 架构在干净文本上成立得很好** —— 9B 10/10、4B 9/10。
   这是对 §6.1「架构成立」的独立确认，且这次用的是**语义标注的意图选项**（不是关键词命中）。
2. **致命：我上一轮那个猜想被证伪。** 我在 §7.5 写过「语义模型可能比子串匹配更抗 ASR 损伤」——
   数据说**不成立**：损坏转写上 4B 掉到 4/10、9B 掉到 6/10。**损伤不是表层错字，是内容被销毁。**

看句 2 就清楚为什么：「點證明你唔係呃人嘅」→「点进营，你有细节整改。」
——**这已经不是拼写错误，是语义消失**，人类也无法从转写还原意图。
而句 7（去→写，仅表层错字）两模型都判对。

**所以是两种regime**：
- **表层损伤**（去→写、倉→钱、單號→单后）→ 可恢复，模型也吃得住
- **内容销毁**（点进营/你有细节整改、你咪再骗几条呢个）→ **任何后处理都无解**

这解释了 §9.1 的「热词扩容零增益」：**词表偏置治不了内容销毁。**

### 10.2 ⭐ V-4 小模型表达校正：不成立（用户假设的直接检验）

**用户假设**：「用户输入的时候小模型做表达校正」——参考 Type4Me / akang-ai-voice-input / VoxType
三个语音输入法的形态（`录音 → ASR → 小模型清理 → 上屏`）。

**先修正上一轮实验的一个漏洞**：V-3b **没给步骤上下文**，而上下文恰是「内容销毁型」句子唯一可能的救赎。
本轮补上步骤上下文（第 3 步 / 索取号码 / 客户常见反应），四条件对照：

| 条件 | 4B | 9B |
|---|---|---|
| clean+ctx（天花板） | 9/10 | 9/10 |
| local+ctx（现状） | **5/10** | **6/10** |
| cloud+ctx（换 ASR 端到端） | 5/10 | 6/10 |
| **rewrite+ctx（小模型校正后判定）** | **5/10** | **6/10** |

**`rewrite` 与 `local` 逐句完全一致，连失败的句子都相同。校正层净价值 = 0。**

**为什么？看校正层实际产出就懂了**：

| 原转写 | 小模型「还原」后 |
|---|---|
| 你咪再骗几条呢个？ | 你咪再**騙**幾**條**呢**個**？ |
| 点进营，你有细节整改。 | 點進營，你有**得**細**緻**整改。 |
| 我已经当做好耐啦。 | 我已經當做好耐啦。 |
| 你哋个钱喺边度噶？ | 你哋個錢喺邊度噶？ |

**它一个字都没改对——只做了繁简转换。** 唯一的变化是 4B 在句 2 插了个「得」字。
原因很直接：**模型无从知道客户实际说了什么**。文本里没有这个信息时，
让它「还原客户本意」只可能有两种结果——**照抄原文（本轮的实际行为，安全但无用）**
或**编造（危险）**。它选择了照抄，这是对的，但也说明这条路没有信息可提取。

**为什么语音输入法那套不适用**（三个参考项目都读了）：

| | 语音输入法（Type4Me / VoxType / akang） | 我们（A 线外呼） |
|---|---|---|
| 说话人意图 | **就是要产出文字**，配合、吐字清楚 | 接听陌生来电，可能怀疑/不耐烦/随口应答 |
| 拾音 | 近讲麦 | 电话链路 + 环境噪声 |
| ASR 错误类型 | **表层**：语气词、重复、断句、回改 | **含内容销毁**：「點證明你唔係呃人嘅」→「点进营，你有细节整改。」 |
| 清理目标 | **可读性**（去口水词/补标点/分段） | 意图可判性 |
| 项目自己的证据 | Type4Me 的 Quick Mode **直接绕过 LLM** 保延迟；Voice Polish 的清单全是表层现象；<br>VoxType 的 LLM 校正**默认关**、且需先开标点；<br>**akang 明确反向**——「avoiding the extra delay of a separate ASR-to-LLM pipeline」，<br>用单一 Realtime omni 模型读音频 | —— |

**结论：校正层治的是表层，我们的病有一部分是内容层。表层能治的部分（去口水词/补标点）
对本产品无价值——我们不需要可读的文字，我们需要能判意图的文字。**

**五条路全部测完，排序如下：**

## 11. ⭐ V-5 验证通过：「低置信度 → 显式澄清」这条路成立

**待验前提**（可证伪）：*存在一个可观测信号，能把「判对了」与「判错了」分开。*
若不存在（模型在损坏输入上"自信地错"）→ 这条路与前五条同样判死。

样本：**65 条已标注转写**（10 句 × 词表 3 档 × 本地/云端两后端，去重后），
同一步骤上下文、同一份 12 选项表。三个候选信号同台比较。

### 11.1 信号 A（概率间距 margin）——有效，且零成本

`margin = logprob(top1) − logprob(top2)`，**不依赖归一化假设**（V1-03 已证 logprob 未归一化），
只用作序数信号。**它就在判定调用本来就会返回的 logprobs 里 → 零额外调用、零额外延迟。**

工作曲线（分四位，左=最不确定 → 右=最确定，格式 `[区间]错/总数`）：

| 模型 | 最低位 | 次低位 | 中高位 | **最高位** |
|---|---|---|---|---|
| 4B | [0.00,0.38] **13/16 错** | [0.38,0.75] 11/16 | [0.75,4.25] 9/16 | [4.75,6.62] **2/16** |
| 9B | [0.38,1.00] **14/16 错** | [1.00,3.00] 10/16 | [3.00,4.25] 6/16 | [4.25,5.88] **0/16** |

**单调，且最高位近乎无错**。中位数分离：4B 对的 4.50 vs 错的 0.50（9×）；
9B 对的 4.25 vs 错的 1.06（4×）。

**推测机制**：margin 实际在追踪**文本质量**——干净文本 → 高 margin 且判对；
损坏文本 → 低 margin 且判错。**这恰恰是我们要的行为**（该澄清的正是文本坏掉的那些轮）。

### 11.2 信号 C（模型选「其他」）——精确率 100%，但只在 9B 上出现

| 模型 | 选「其他」轮数 | 其中判错 |
|---|---|---|
| 4B | **0/65**（内建不确定出口完全不用） | 0 |
| 9B | **7/65** | **7（100%）** |

9B 一旦选「其他」，**必错**。作信号零误伤，但召回低（7/30）。

### 11.3 信号 B（模型自陈「你能不能确定」）——**无效**

另发一次 noul 问「只看这句话，你能不能确定客户意图」：

| 模型 | 对的 中位 | 错的 中位 |
|---|---|---|
| 4B | 0.47 | **0.47（完全相同）** |
| 9B | 0.88 | 0.78（曲线近乎平坦：11/8/6/4/1） |

**模型无法内省自己的不确定**，而且它要多花一次调用。→ **弃用。**
（干净的负结果：**logits 比模型自己说出来的更知道它不知道。**）

### 11.4 组合规则与实际代价

**规则：`margin ≤ 30 分位` OR `选了「其他」` → 本轮改走显式澄清，不执行判定结果。**

| 模型 | 触发 | 捕获错误 | 误伤正确 | 精确率 |
|---|---|---|---|---|
| 4B | 21/65 | 16/35 = **46%** | 5 轮 | 76% |
| **9B** | 21/65 | **19/30 = 63%** | **2 轮** | **90%** |

**9B 是最佳底座**：触发 21 轮（占全体 32%）里 19 轮本来就在错，只搭上 2 个正确轮。
即 **约 32% 的轮次会听到一句澄清，换来 63% 的判定错误被拦下，代价是 2/35 的正确轮**。
（组成：仅 margin 触发 14 轮、仅「其他」触发 7 轮。）

**这与前五条路的根本差别**：热词 / 音学校正 / 小模型校正 / 语义直判 全部是"更努力地听懂"，
在**信息已销毁**的输入上无解；本条**不试图听懂，而是承认听不懂并改走修复动作**——
它要的不是信息，是一个可观测的「我不知道」信号，而这个信号存在。

### 11.5 必须说清的四条限制（否则这条验证不成立）

1. **样本多样性只有 10 句**：65 条是 10 句 × 3 档词表 × 2 后端**扩展出来的**，不是 65 个独立场景。
   margin 分布可能是**句级特异的**。→ **必须在更大的真实通话标注集上复验**（当前唯一的关键缺口）。
2. **30 分位阈值是在这批数据上事后选的** → **过拟合风险**。生产阈值必须在**留出集**上重新拟合。
3. **margin 未标定**（V1-03）：这里只用它的**序数**性质，实验设计刻意不依赖标定，
   所以结论不受 V1-03 影响；但**不能把 margin 当概率解释**（不能说「margin 4.5 = 95% 把握」）。
4. **本轮测的是「能不能识别该澄清」，不是「澄清之后有没有变好」**。
   后者（澄清轮的客户回应、通话是否走回正轨）**未测**，属下一阶段。

## 12. V-1 结论与下一步

**已可定论的四条**：

1. **架构成立且零新依赖**：用 mlx_lm 原生 `logprobs` 做 prefill-only typed decision
   （`noul`/`choice`/`score`），**不需要 LAY A、不需要第二个运行时**。
2. **收益来源要重新表述**：不是"换个更快的模型"，而是**把生成式判定换成判类型判定**——
   9B 即使 413ms，对比现状（生成式 judge / `timeout=20s` / 迟一轮 / pending+TTL+store 守卫）
   仍是几十倍提速且同轮同步。**`docs/A_LINE_LOGIC.md` §10.4 的「迟一轮」结构洞具备消除条件。**
3. **两模型按用途分工，不是二选一**：4B（176ms，判据内）做**必须同步**的判定；
   9B（413ms，更准）做**可以多花 400ms** 的判定。分工线由「这个判定的延迟预算是多少」决定。
4. **两条硬实现约束**：① 候选清单进「按步静态」system 前缀（V1-08，176 vs 348ms）；
   ② 标记用单 token 符号、按 token id 映射（V1-02/V1-10）；③ 阈值逐问题经验拟合，不信自报置信度（V1-03）。

**仍待补的五条**：

- **V1-11 的近同文坍塌**：机制未清（`v1f` 显示破缓存能救，`v1g` 显示生产形状本就没事）——
  需要一个隔离变体把「缓存」与「近同文上下文」分开。**虽然不污染生产形状，但它是唯一没查清的异常。**
- **准确率放大样本**：n=7 定不了 4B/9B 优劣 → 用 V-4 的真实挖掘语料（L-① 漏网轮 + QA 问法）扩到 50–100 例。
- **V1-03 量化对照**：8bit 4B 的 logprob 是否归一化、是否更锐 → 空闲端口起第二实例对比。
- **多 token 选项打分**：本轮用单 token 标记绕开，需测「选项原文前缀打分」方案（更贴近运营写法）。
- **V1-08 边界**：步骤切换时静态前缀会变 → 步骤切换那一次的冷启成本要测
  （`prompt-cache-size 128` 可能同时保住多步前缀）。
